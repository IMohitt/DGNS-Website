# DGNS Advisors Website

## Project Overview

Production React website for DGNS Advisors LLC FZ. It presents UAE business
setup, accounting and bookkeeping, VAT, Corporate Tax, advisory, company
information, contact/WhatsApp journeys, and the separate DGNS Tour & Travels
offering.

Production content routes include:

- `/`
- `/services` and the Business Setup, Accounting & Bookkeeping, VAT, Corporate
  Tax, and Advisory service pages
- `/business-setup`, Mainland, Dubai, Abu Dhabi, Sharjah, Ajman, and Free Zone
- `/about` and `/contact`
- `/tour-travels`, `/tour-travels/destinations`,
  `/tour-travels/experiences`, and `/tour-travels/packages`
- `/privacy-policy` and `/terms`

Unknown URLs render the branded 404 page. Deployment configuration preserves
client-side routes without redirecting unknown URLs to the homepage.

## Technology

- React 19 and TypeScript
- Vite
- Tailwind CSS 4
- React Router
- Framer Motion with reduced-motion support
- React Hook Form
- Lucide icons
- Self-hosted Manrope variable font with `font-display: swap`

## Production Build

```bash
npm run build
```

The production output is written to `dist/`. The build also generates an HTML
shell for every production route plus `404.html`, giving direct visits stable
metadata while the React application loads. To serve that output locally:

```bash
npm run preview
```

## Contact Configuration

Verified public contact and company values live in
`src/config/siteConfig.ts`. Update the company name, telephone, emails,
address, website, and verified social URLs there instead of duplicating them in
components.

### How to Change the WhatsApp Number

1. Open `src/config/siteConfig.ts`.
2. Update `phone` for the displayed telephone number.
3. Update `whatsapp` using digits only, including country code and without `+`,
   spaces, or punctuation.
4. Run `npm run build` and test a generated `wa.me` link on mobile and desktop.

WhatsApp URLs and message encoding are centralized in
`src/utils/whatsapp.ts`.

## How to Update Services

Reusable service copy and links are primarily maintained in
`src/data/services.ts`. Business-setup content is maintained in
`src/data/businessSetup.ts`. Keep factual regulatory copy cautious and verify
time-sensitive information before publishing.

## How to Add Travel Packages

Travel data is centralized in:

- `src/data/destinations.ts`
- `src/data/travelExperiences.ts`
- `src/data/travelPackages.ts`
- `src/data/travel.ts`

Add responsive image families under `src/assets/images/travel/`, preserve the
declared image dimensions, and include descriptive alt text. Do not publish a
price, discount, availability claim, or inclusion unless it is confirmed.
Package WhatsApp messages are generated from the centralized package record.

## SEO

Page titles, descriptions, canonical links, Open Graph/Twitter data, and JSON-LD
are generated by the shared metadata/schema components. The production base URL
defaults to `https://dgnsadvisors.ae` and can be set with `VITE_SITE_URL`.

Static crawler files are copied from:

- `public/sitemap.xml`
- `public/robots.txt`

Update the sitemap whenever an indexable route is added or removed. Do not add
filtered query URLs, test routes, or 404 pages. A final approved social-sharing
image must be added separately before enabling a site-wide `og:image`.

## Environment Variables

Copy `.env.example` to the environment configured by the deployment provider.
No secret is required for the current contact or WhatsApp flows.

| Variable | Purpose |
| --- | --- |
| `VITE_SITE_URL` | Canonical/schema base URL; production should remain `https://dgnsadvisors.ae` |
| `VITE_GA_ID` | Reserved for a future consent-aware Google Analytics integration |
| `VITE_META_PIXEL_ID` | Reserved for a future consent-aware Meta Pixel integration |

Analytics and Meta Pixel scripts are intentionally not initialized by the
current build. Do not add tracking IDs until the matching implementation,
consent behavior, and privacy wording have been approved. Never commit secrets
to a Vite variable because `VITE_*` values are exposed to the browser.

## Deployment to Netlify

1. Connect the repository in Netlify.
2. Use `npm run build` as the build command.
3. Use `dist` as the publish directory.
4. Configure `VITE_SITE_URL=https://dgnsadvisors.ae` and any deliberately
   enabled optional variables.
5. Deploy and attach the custom domain `dgnsadvisors.ae`.
6. Verify DNS and SSL manually; this project does not change DNS.

`netlify.toml` defines the build, safe baseline headers, and immutable caching
for hashed assets. Production routes have generated static shells, while
`public/_redirects` contains permanent redirects for known legacy URLs. Netlify
automatically uses the generated `404.html` for unknown paths.

## Deployment to Vercel

1. Import the repository in Vercel.
2. Select the Vite framework preset if it is not detected automatically.
3. Use `npm run build` and output directory `dist`.
4. Configure `VITE_SITE_URL=https://dgnsadvisors.ae`.
5. Deploy, attach the domain, and verify DNS/SSL manually.

`vercel.json` provides SPA rewrites, baseline headers, and immutable hashed-asset
caching without adding provider-specific application code.
